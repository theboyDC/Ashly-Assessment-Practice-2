=== Question 1 ===
Access modifiers are keywords in Java that control which other classes or parts of your code are allowed to see and use a field, method, or class. They matter because not everything in your code should be freely available to everyone — just like you would not give a stranger your bank PIN, some data in your programme needs to be protected.

The private modifier means that only code inside that same class can access that field or method. You would use private for sensitive data like a password or a bank balance, because you do not want any other class to read or change it directly. The public modifier means that any class anywhere in your project can access it. You would use public for things you intentionally want to share, like a method that other classes need to call. The protected modifier sits in between — it allows access from within the same class, any class in the same package, and any subclass that extends it. You would use protected when you are building a parent class and want child classes to be able to use something, but you still do not want the whole world accessing it.

Making everything public is a problem because it removes all protection from your code. Imagine you have a BankAccount class and you make the balance field public. Any other class could write bankAccount.balance = 1000000 and change it without going through your proper deposit or withdraw methods. This breaks the idea of keeping data safe inside the class. A concrete example would be:

public class BankAccount {
    private double balance;

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    public double getBalance() {
        return balance;
    }
}

Here balance is private, so nobody outside the class can change it directly. They have to use the deposit method, which checks that the amount is valid first. If balance were public, anyone could skip that check and set it to whatever they wanted.


=== Question 2 ===
A constructor is a special block of code inside a class that runs automatically when you create a new object from that class. Its job is to set up the object right away — giving its fields their starting values so the object is ready to use from the moment it is created. The constructor is always named exactly the same as the class itself, and it has no return type at all, not even void.

A method is a block of code inside a class that performs a specific task. Methods are given names that describe what they do, they have a return type (or void if they return nothing), and they only run when you explicitly call them. You can call a method as many times as you like on an object.

The key differences are: a constructor has the exact same name as the class while a method has its own descriptive name; a constructor has no return type at all while a method must declare one (even if it is void); and a constructor is called automatically when you use the new keyword to create an object, while a method is called manually whenever you need it. Here is a simple Java example that shows both in the same class:

public class Animal {
    String name;
    int age;

    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String describe() {
        return name + " is " + age + " years old.";
    }
}

In this example, Animal(String name, int age) is the constructor — it runs the moment you write new Animal("Dog", 3). The describe() method is separate and only runs when you call it like myAnimal.describe().


=== Question 3 ===
Loops in Java let you repeat a block of code multiple times, just like in Python, but the syntax is different and Java requires you to be specific about types. The standard for loop has three parts separated by semicolons inside the parentheses: the first part is the initialisation where you create and set your counter variable, like int i = 0; the second part is the condition that is checked before every loop — if it is true the loop runs, if it is false it stops, like i < 10; and the third part is the update that happens after every loop, like i++ which adds 1 to i each time. A full example looks like this:

for (int i = 0; i < 10; i++) {
    System.out.println(i);
}

The enhanced for loop, also called the for-each loop, is used when you want to go through every element in an array or a collection like a List. Instead of the "in" keyword that Python uses, Java uses a colon. You also have to declare the type of the elements. An example looks like this:

String[] fruits = {"apple", "banana", "mango"};
for (String fruit : fruits) {
    System.out.println(fruit);
}

You would choose the for-each loop when you just need each element and do not care about its position. You would choose the standard for loop when you need the index, for example if you want to know which position you are at or if you want to loop backwards.

The while loop is different from both because it only has a condition — it has no built-in counter or update step. You use it when you do not know in advance how many times you need to loop, and you just want to keep going as long as something is true. An example looks like this:

int x = 0;
while (x < 5) {
    System.out.println(x);
    x++;
}

The loop checks the condition before each run and stops as soon as it becomes false, so you have to remember to update x yourself inside the loop, otherwise it will run forever.


=== Question 4 ===
A class in Java is like a blueprint or a template. It describes what something should look like and what it can do, but it is not the actual thing itself. For example, a Dog class would describe that every dog has a name and an age, and that every dog can bark — but the class itself is not a real dog. An object is the actual thing that gets created from that blueprint. When you write new Dog("Rex", 3) in Java, you are creating a real Dog object based on the class.

The reason grouping data and behaviour together in a class is better than having separate variables and functions scattered through a script is that everything that belongs to a concept stays in one place. If you have a Dog class, the name and age live inside it, and the bark method lives inside it too. When you need to change something about how dogs work, you only have to look in one place. If those things were scattered as loose variables and functions across your code, it would become very confusing and hard to manage, especially as the programme grows.

Here is a simple Java example that shows a class and how to create objects from it:

public class Dog {
    String name;
    int age;

    public Dog(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public void bark() {
        System.out.println(name + " says: Woof!");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog myDog = new Dog("Rex", 3);
        myDog.bark();
    }
}

Here Dog is the class and myDog is the object. The class defines the structure and the behaviour, and the object is the actual instance you work with in your programme.
